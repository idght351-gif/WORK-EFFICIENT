# 마일 좌석 조회 절차 가르치기

사용자가 화면을 보며 "다음은 이 버튼"이라고 알려 주면, 그대로 한 단계씩 해 보고 절차서에 적는 시간이에요. 목표는 다음부터 Claude 혼자 절차서만 보고 똑같이 반복하는 거예요.

## 순서

1. `award-tracker/playbook/PLAYBOOK.md` 를 처음부터 끝까지 읽어요. 0장 규칙(천천히 기다리기, 하지 않는 것, 멈추는 때)은 가르치는 중에도 지켜요.
2. Claude in Chrome 이 연결돼 있는지 확인해요 (`tabs_context_mcp`). 안 되면 사용자에게 `/chrome` 으로 연결해 달라고 해요.
3. 노선 하나로 연습해요. `routes.json` 에 노선이 없으면 사용자에게 연습할 노선을 물어 `python award-tracker/tools/award.py start` 전에 routes.json 에 넣어요 (사용자 확인 후).
4. **한 단계씩**:
   - 지금 화면을 보고(스크린샷 + 페이지 글자) 무엇이 보이는지 한두 줄로 말해요.
   - 다음에 누를 것 같은 버튼을 말하고, 사용자가 맞다고 하거나 다른 버튼을 알려 줄 때까지 기다려요. 사용자가 위치를 말로 알려 주면("오른쪽 위 파란 버튼") 그걸 찾아서 "이 버튼 맞나요? (화면 글자: …)"로 확인받아요.
   - 누르고 `python award-tracker/tools/award.py wait click` (결과를 불러오는 버튼이면 `wait search`).
   - 바뀐 화면을 확인하고, 절차서 표의 그 단계 줄을 채워요: 이 화면인지 확인하는 단서 / 버튼 이름(화면 글자 그대로)과 위치 설명 / 기다림 / 됐는지 확인하는 단서. 좌표는 적지 않아요.
5. 캘린더가 나오면 날짜별 마일을 페이지 글자로 읽는 방법(어디에 어떤 글자로 나오는지, 좌석 없음은 어떻게 보이는지)을 2-9 에 적고, 실제로 `save` 해 봐요.
6. 상세 확인(3장)도 같은 방식으로 한 번 끝까지 해요. 결제 단계 직전에서 멈춰요.
7. 처음 보는 팝업 · 배너 · 오류는 6장 예외 표에 추가해요.
8. 끝나면:
   - 절차서 맨 위 상태를 `가르치기 완료 (날짜)` 로, 아직 ❓ 가 남았으면 `일부 가르침 (날짜) — 남은 ❓: …` 로 바꿔요.
   - "가르친 기록" 표에 한 줄 추가해요.
   - 절차서만 commit · push 해요: `git add award-tracker/playbook && git commit -m "마일 좌석 절차서: …" && git pull --rebase --autostash && git push`
   - 연습 때 저장된 결과가 있으면 `finish ok` → `publish` 해요.
9. 마지막으로 "이제 제가 절차서만 보고 처음부터 혼자 해 볼까요?" 하고 물어요. 하겠다고 하면 `award-search` 순서대로 하되, 단계마다 무엇을 하는지 짧게 말해서 사용자가 지켜볼 수 있게 해요.
