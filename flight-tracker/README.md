# ✈︎ 항공권 가격 추적기

Google 항공권 가격을 **앱에서 [지금 다시 조회]를 누를 때** 조회해서 기록하고, 가격 추이 그래프를 보여줍니다. 목표가(`alert_below`)를 정해 두면 그 이하로 떨어졌을 때만 알림 메일을 보냅니다.
GitHub 하나로 모든 것이 돌아갑니다 (서버·DB 불필요, 무료).

```
앱 [지금 다시 조회] 버튼 (GitHub Actions 실행)
  └─ SerpApi 로 Google 항공권 검색 → 출발 시간대 안 최저가 선택
  └─ site/data/ 에 날짜별 기록 저장 (저장소에 자동 commit)
  └─ 목표가 이하 → Gmail 로 알림 메일
  └─ GitHub Pages 로 그래프 웹페이지 배포
```

정기(예약) 조회와 최저가 리포트 메일은 꺼 두었어요(검색 횟수 절약). 노선 상세 화면의 **[지금 다시 조회]**(그 노선만) 또는 목록 아래 **[전체 다시 조회]**를 누르면 앱이 GitHub Actions 를 실행하고, 1~2분 뒤 결과가 화면에 바로 반영돼요(앱 설정의 GitHub 연결 필요). 버튼 아래에 마지막 조회 시각과 검색 사용 수가 보여요. 다시 매일 조회하려면 워크플로에 `schedule` cron 을 넣고 `RUNS_PER_DAY` · `SCHEDULE_KST` 를 맞추면 되고, 리포트 메일은 `SEND_REPORT: "true"` 로 켜요.

## 처음 설정 (한 번만, 약 10분)

### 1. SerpApi 키 발급
1. https://serpapi.com 가입 (무료 플랜: 월 250회, 가입 시 휴대폰 인증 필요)
2. 대시보드의 **API Key** 복사

> 조회 1번에 편도는 검색 1회, 왕복은 2회, 다구간은 구간 수만큼 씁니다. 지금 설정(왕복 1개 + 4구간 1개, 하루 1번)이면 하루 6회, 한 달 약 180회로 무료 플랜(월 250회) 안이에요. 노선이나 조회 횟수를 늘리면 한도를 넘을 수 있으니 추적 페이지의 SerpApi 카드에서 확인하세요.
>
> 정기 메일은 예약 실행과 Actions 탭의 수동 실행(Run workflow) 때만 보내고, 코드 push 로 실행될 때는 보내지 않아요. 그래프와 기록은 하루 1칸이며, 그날 마지막 조회 값이 남습니다.
>
> 추적 페이지 맨 위에 **SerpApi 남은 검색 수, 다음 갱신일, 갱신일까지 예상 사용량**이 보여요. 가격 조회 때마다 SerpApi Account API(검색 횟수에 포함되지 않음)로 함께 확인합니다. API 키와 계정 이메일은 저장하지 않아요.

### 2. Gmail 앱 비밀번호 발급
1. Google 계정 → 보안 → **2단계 인증** 켜기 (필수)
2. https://myaccount.google.com/apppasswords 에서 앱 이름(예: flight) 입력 → 16자리 비밀번호 복사

### 3. GitHub 저장소에 비밀값 등록
저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `SERPAPI_KEY` | SerpApi API 키 |
| `GMAIL_USER` | 보내는 Gmail 주소 |
| `GMAIL_APP_PASSWORD` | 16자리 앱 비밀번호 (공백 없이) |
| `ALERT_EMAIL` | 알림 받을 주소 (생략하면 `GMAIL_USER` 로 받음) |

### 4. GitHub Pages 켜기
저장소 → **Settings → Pages → Source: GitHub Actions** 선택

### 5. main 브랜치에 합치기
GitHub 예약 실행은 **기본 브랜치(main)에서만** 돌아갑니다. 이 작업 브랜치를 main 에 merge 하세요.

### 6. 첫 실행
**Actions 탭 → 항공권 가격 체크 → Run workflow**. 끝나면 `https://<아이디>.github.io/<저장소이름>/` 에서 확인할 수 있어요.

## 노선 추가 / 수정

`flight-tracker/routes.json` 을 GitHub 에서 직접 수정하면 됩니다. 웹페이지의 **+ 노선 추가하기** 화면에서 입력하면 붙여 넣을 내용을 만들어 줘요.

```jsonc
{
  "id": "icn-nrt-20261220",     // 고유 이름 (영문·숫자·하이픈)
  "name": "서울 → 도쿄",
  "from": "ICN", "to": "NRT",   // 공항 코드 (김포 GMP, 김해 PUS, 오사카 KIX, 후쿠오카 FUK …)
  "date": "2026-12-20",          // 가는 날
  "return_date": null,           // 왕복이면 "2026-12-24" (가격은 왕복 총액)
  "depart_after": "09:00",       // 이 시각부터
  "depart_before": "12:00",      // 이 시각까지 출발하는 편 중 최저가
  "adults": 1,
  "travel_class": "economy",     // economy / premium_economy / business / first
  "max_stops": null,             // null = 상관없음, 0 = 직항만, 1 = 1회 경유 이하
  "alert_below": 250000,         // 이 가격(원) 이하면 메일
  "active": true                 // false 로 바꾸면 일시 중지
}
```

routes.json 을 저장(commit)하면 바로 한 번 실행되어 첫 가격이 기록됩니다.

## 동작 규칙
- **알림 중복 방지**: 목표가 아래로 처음 내려갈 때, 또는 직전 알림보다 더 내려갔을 때만 메일을 보냅니다. 다시 목표가 위로 올라가면 초기화되어 다음 하락 때 또 알려줍니다.
- **출발일이 지나면** 자동으로 조회를 멈춥니다 (API 사용량 절약).
- **조회 실패** 시 3번 재시도하고, 그래도 실패하면 그날은 "조회 실패"로 기록되고 그래프 선이 끊겨 보입니다.
- 가격은 **한국 기준(KRW, gl=kr)** 으로 검색합니다. 저가항공은 수하물 미포함 가격일 수 있어요.

## 휴대폰에서 바로 저장 (GitHub 연결, 처음 한 번)
추적 페이지 맨 아래 **⚙︎ 앱 설정**에서 GitHub 접근 키를 한 번 연결하면, 노선 추가 · 조건 바꾸기 · 삭제를 앱에서 버튼 한 번으로 저장하고 바로 조회해요.
- 키 만들기: GitHub → Settings → Developer settings → **Tokens (classic)** → Generate new token → **repo** 체크 (앱 설정의 버튼을 누르면 미리 채워진 화면이 열려요)
  - 저장소 주인이 아니어도 이 저장소의 협업자(Write)면 연결돼요. fine-grained 키는 다른 사람 계정의 저장소를 고를 수 없어서 classic 키를 써요.
  - 저장소 주인이라면 fine-grained 키(이 저장소만, Contents: Read and write)를 붙여 넣어도 돼요.
- 키는 그 휴대폰(브라우저)에만 저장되고, `flight-tracker/routes.json` 을 고칠 때만 써요.
- 노선이 바뀌어 저장되면 **바뀐 노선만** 바로 조회해요(검색 횟수 절약).

## 추적 조건 바꾸기 (직항만 · 시간 · 인원 등)
추적 페이지에서 노선을 누르고 **조건 바꾸기**를 누르세요. 경유(상관없음 / 직항만 / 1회 이하), 출발 시간대, 인원, 좌석, 목표가를 고르면 `routes.json` 에서 그 노선 항목을 대신할 내용이 만들어져요. GitHub 에서 그 항목을 바꿔 Commit 하면 바로 한 번 조회되고, 이후 정해진 시각에 조회돼요.

## 다구간 여정
노선 추가하기 / 조건 바꾸기 화면에서 **다구간**을 고르면 구간을 2~6개까지 넣을 수 있어요(예: 인천 → 삿포로, 삿포로 → 도쿄, 도쿄 → 인천). 구간마다 출발 시간대를 따로 정할 수 있고, 경유·인원·좌석 조건은 모든 구간에 똑같이 적용돼요.
- 같은 날 이어지는 구간은 앞 편 도착 후 **최소 2시간 뒤 출발**하는 편만 골라요(노선에 `"min_connection_min": 90` 처럼 바꿀 수 있음).
- 1구간에서 가장 싼 편을 고르고, 그 편에 이어지는 다음 구간 중 가장 싼 편을 고르는 식으로 끝까지 이어서 전체 여정 총액을 기록해요.
- **조회할 때 구간마다 검색 1회**를 써요. 4구간을 하루 1번 조회하면 한 달 약 120회예요.

```json
{
  "id": "icn-cts-nrt-icn-20270629",
  "name": "홋카이도·도쿄",
  "legs": [
    { "from": "ICN", "to": "CTS", "date": "2027-06-29", "depart_after": "10:00" },
    { "from": "CTS", "to": "NRT", "date": "2027-07-02" },
    { "from": "NRT", "to": "ICN", "date": "2027-07-05", "depart_after": "12:00" }
  ],
  "adults": 1, "travel_class": "economy", "max_stops": 0, "alert_below": null, "active": true
}
```

### 구간별 편도 합산 (`"separate_tickets": true`)
Google 항공권 다구간 검색은 여정 전체를 **한 장의 항공권으로 팔 수 있는 조합**만 보여 줘요. 가는 편과 오는 편 공항이 다르고 저가항공을 섞어 타는 여정(예: 인천 → 고베, 간사이 → 김포)은 결과가 0개로 나올 수 있어요. 구간에 나라 전체(`JP`)·도시 코드(`SEL`)·여러 공항이 들어가면 자동으로 이 방식으로 검색하고, 앞 구간 도착지와 다음 구간 출발지가 같은 넓은 곳(예: `JP` → `JP`)이면 **같은 도시에서 이어지는 편끼리만** 묶어 합계가 가장 싼 조합을 골라요(예: 부산→간사이 + 고베→인천). 그 밖의 노선도 `"separate_tickets": true` 를 넣으면 구간마다 편도로 따로 검색해 가장 싼 편끼리 합산해요(검색 횟수는 구간 수만큼으로 같음). 메일에는 구간별 가격도 함께 나와요.

## 나라 전체 · 월·요일로 가장 싼 날 찾기
- 공항 칸에 `JP`(일본 전체)를 넣을 수 있어요(앱의 [도착 일본 전체] 버튼, Google 위치 ID `/m/03_3d` 로 검색). 한국 전체로 출발하면 Google 이 결과를 주지 않아서 **한국은 인천·김포·청주(`ICN,GMP,CJJ`)** 로 검색해요([출발 인천·김포·청주] 버튼, `KR` 을 넣어도 같음).
- 왕복·편도에서 **여러 날짜 중 찾기**를 고르고 가는 날 후보를 원하는 만큼 추가하면, 그 날짜들 중 **가장 싼 출발일**을 찾아요. 왕복은 여행 기간(박)을 정해요. (`"flex": {"dates": [...]}`. 예전 방식인 `months` + `weekdays` 도 계속 읽어요.)
- 조회 방법: SerpApi **가격 달력**(`google_flights_calendar`) 1회로 날짜별 가격을 받아 요일로 거르고 가장 싼 날을 고른 뒤, 그날 **상세 검색**(편도 1회 · 왕복 2회)으로 실제 항공편을 확인해요. 앱과 메일에 가장 싼 날과 다음 후보 날짜들이 함께 나와요. 가격 달력이 비어 날짜마다 직접 검색한 경우에는 항공편 목록에 **후보 날짜의 편이 가격순으로 섞여** 나오고 줄마다 날짜가 붙어요(추가 검색 없음).

```json
{ "id": "kr-jp-202702", "name": "한국 → 일본", "from": "KR", "to": "JP",
  "flex": { "dates": ["2027-02-12", "2027-02-13", "2027-02-19"], "trip_days": null },
  "adults": 1, "travel_class": "economy", "max_stops": 0, "active": true }
```

## 왕복 조합 고르기 (1단계 가는 편 → 2단계 오는 편)
왕복 노선 상세 화면에서 **① 가는 편**을 누르면 **② 그 가는 편과 묶을 수 있는 오는 편**과 왕복 총액, 최저가 조합 대비 차이(+얼마)가 나와요. 오는 편까지 고르면 위쪽에 고른 조합의 총액이 표시돼서 Google 항공권이나 Kayak 에서 그대로 찾아 예약하면 돼요.
- 위쪽 **[가는 편 먼저 | 오는 편 먼저]** 로 순서를 바꿀 수 있어요. 오는 편 먼저는 지금까지 조회해 둔 조합(가는 편 상위 3개 + 앱에서 조회한 편)을 오는 편 기준으로 다시 묶어 보여 주고, 아직 조합을 조회하지 않은 가는 편은 아래에서 눌러 조회할 수 있어요.
- 가는 편 **상위 3개**의 오는 편은 조회할 때 미리 받아 둬요. 1위는 추가 검색 없이, 2·3위는 편마다 오는 편 검색 1회(가는 편 검색은 같은 조건이라 SerpApi 캐시로 무료) → 왕복 노선 조회마다 2회 더 들어요. 상위 개수는 `check_prices.py` 의 `PREFETCH_TOP`.
- 다른 가는 편은 앱에서 **[이 가는 편의 오는 편 조회]** 를 누르면 GitHub Actions 가 그 편만 조회해요(검색 1~2회, 약 1~2분). 앱 설정의 GitHub 연결이 필요하고, 결과는 `site/data/returns/<노선id>.json` 에 저장돼 다음에 열 때 바로 보여요.

## 숨기기 (조회 멈춤)
메인 목록에서 카드를 **왼쪽으로 밀면 [숨기기]** 버튼이 나오고, 누르면 바로 숨겨져요(잠깐 뜨는 **되돌리기**로 취소 가능). 노선 상세 화면 맨 아래 **[목록에서 숨기기 (조회 멈춤)]** 를 눌러도 그 노선은 조회를 멈추고(`"active": false`) 메인 목록에서 빠져요. 숨긴 노선과 출발일이 지난 노선은 목록 아래 **숨긴 항공권 N개** 를 눌러야 보이고, 거기서 **[다시 보이기]** 를 누르면 조회가 다시 시작돼요(그때 한 번 조회). 기록은 그대로 남아요.

## Kayak · Skyscanner 비교
노선 상세 화면과 알림 메일에 **Kayak 비교**, **Skyscanner 비교** 링크가 있어요. 누르면 같은 출발지·도착지·날짜·인원·좌석 등급으로 검색 결과가 열립니다(직항만 추적 중이면 직항 필터도 켜져요).
- 두 사이트는 무료로 쓸 수 있는 가격 API가 없어서, 가격을 자동으로 기록하지는 않고 링크로 바로 비교하는 방식이에요.
- 출발 시간대 조건은 주소로 지정할 수 없어서 각 사이트에서 직접 설정해야 해요.

## 휴대폰 홈 화면에 앱으로 추가
추적 페이지 주소(`https://<아이디>.github.io/<저장소>/`)를 공유하면, 받은 사람도 홈 화면에 앱처럼 추가할 수 있어요.
- **iPhone (Safari)**: 공유 버튼 → "홈 화면에 추가"
- **Android (Chrome)**: 오른쪽 위 ⋮ → "홈 화면에 추가" 또는 "앱 설치"

열 때마다 최신 가격을 받아오고, 인터넷이 안 될 때는 마지막으로 본 화면을 보여줘요.

## 주의
- GitHub 무료 계정에서 Pages 를 쓰려면 저장소가 **공개(public)** 여야 합니다. 이 경우 가격 기록(`site/data`)과 노선 정보도 공개됩니다. 메일 주소·API 키는 Secrets 에만 있어 공개되지 않아요.
- GitHub 예약 실행은 몇 분~수십 분 늦게 시작될 수 있고, 저장소에 60일간 활동이 없으면 자동 중지됩니다(매일 기록 commit 이 생기므로 보통은 문제없음).

## 로컬 테스트

cd flight-tracker/tracker
